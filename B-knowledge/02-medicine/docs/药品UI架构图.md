# 药品UI架构图

> 依据：成员A《产品UI与网页前端执行手册》及《用户任务与需求&信息架构与页面流程》。

## 一、药品识别主流程

```mermaid
flowchart TD
    A["首页 /<br/>拍照或上传材料"] --> B["统一上传 /upload<br/>拍照·相册·文件"]
    B --> C["页面内处理状态<br/>上传→清晰度→OCR→图片理解"]
    C --> D{"分类确认 /confirm<br/>这是药品或药品说明书吗？"}
    D -->|是| E["药品结果 /medicine"]
    D -->|不是| F["修正材料类别"]
    D -->|看不清| B
    E --> G{"风险等级"}
    G -->|绿色或黄色| G1["生成家属简报 /family"]
    G -->|红色| G2["自动生成家属简报<br/>有授权联系人则推送"]
    E --> H["重新上传 /upload"]
    E --> I["返回首页 /"]
```

## 四、显示约束

- 手机端单栏；电脑端可将大字用药卡与来源图片区并排展示。
- 首屏不出现长表格、完整说明书原文或成串编码。
- 大字用药卡最多包含四个内容块，每块默认不超过三行。
- 说明书长内容折叠展示；表格在手机端转换为卡片。
- 同一页面只有一个醒目的主按钮。
- 待确认问题不存在时，整个模块隐藏。
- 风险或核对状态不能只用颜色表达，必须同时显示文字和图标。
