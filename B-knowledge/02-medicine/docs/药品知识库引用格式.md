# 交付成员A：药品知识库引用格式

> 交付方：成员B（知识库、内容规则与数据资料）  
> 接收方：成员A（产品、UI与网页前端）  
> 用途：统一药品结果页、详细信息页和“查看信息来源”弹层的来源展示格式。  
> 配套文件：`药品字段文案.md`、`药品UI架构图.md`、`../data/source/资料来源清单.md`。

## 一、什么是知识库引用格式

知识库引用格式不是知识库文件本身，而是知识库、工作流和页面共同遵守的“信息出处协议”。

它规定系统展示每条药品信息时，必须同时说明：

```text
信息是什么
来自哪里
对应哪张图片、哪一页或哪条数据记录
是否已与其他来源核对
存在冲突时应如何展示
```

例如，页面显示“药品名称：苯磺酸氨氯地平片”时，系统不能只返回药名，还要说明该名称来自用户上传的药盒、医保药品编码数据或用户确认。

最小字段对象：

```json
{
  "material_value": "苯磺酸氨氯地平片",
  "catalog_value": "苯磺酸氨氯地平片",
  "display_value": "苯磺酸氨氯地平片",
  "status": "confirmed",
  "sources": [
    {
      "source_id": "MAT-M20260717001-IMG01",
      "source_type": "USER_PACKAGE",
      "short_name": "来自您上传的药盒",
      "location": "图片1，药品名称区域"
    },
    {
      "source_id": "SRC-002-XA10BJB219B002010180532",
      "source_type": "MEDICAL_INSURANCE_CATALOG",
      "short_name": "来自医保药品编码数据",
      "location": "医保药品代码 XA10BJB219B002010180532"
    }
  ],
  "missing_message": null
}
```

页面可以简化显示为：

```text
药品名称
苯磺酸氨氯地平片
来源：您上传的药盒，并已与目录记录对应
```

## 二、引用格式的作用

### 1. 区分不同信息来源

药品结果可能同时来自用户药盒、说明书、医院处方、医保药品编码数据、国家基本药物目录和国家药监局参考信息。引用格式要求这些来源分别保存，避免把编码数据说成“药盒上写的”，也避免把AI解释当作说明书原文。

### 2. 防止数据库错误补全用户材料

医保药品编码数据只用于核对药品身份。用户没有上传用法用量时，系统必须返回“当前材料中未发现”，不能根据编码数据、常识或模型知识自动生成剂量。编码匹配也不代表系统确认该药属于医保报销范围、可以报销或具有特定报销比例。

### 3. 支持药品身份核对

系统同时保留用户材料值和目录值：

```text
用户材料值：5mg
目录记录值：5mg
状态：一致
```

若不一致：

```text
用户材料值：5mg
目录记录值：10mg
状态：需要确认
```

前端必须并排显示，不得自动覆盖。

### 4. 保证结果可追溯

每条重要信息应当能够追溯至图片编号、说明书页码、章节、医保药品代码或批准文号。发生问题时，B可以修正内容，C可以检查工作流，D可以复现测试。

### 5. 统一前端展示

引用格式为A明确规定首屏简短来源、来源详情弹层、冲突提示、多候选卡片和缺失信息文案，避免前端自行解释数据含义。


## 三、四名成员如何使用

```text
B制定来源、状态和引用规则
→ C让工作流按统一JSON返回来源字段
→ A按来源类型和状态展示页面
→ D检查信息是否可追溯、是否发生错误补全
```

| 成员 | 使用方式 |
|---|---|
| B | 为知识字段配置来源编号、来源类型和使用边界 |
| C | 在OCR、目录检索和说明书处理结果中保留来源对象 |
| A | 显示简短来源、来源详情、冲突值和确认按钮 |
| D | 检查每条重要结论能否回到原图片或数据记录 |

## 四、引用原则

1. 用户材料、药品目录和说明书信息必须分开显示，不得混成一个来源。
2. 页面结论必须能够追溯到具体图片、说明书页码或数据记录。
3. 首屏只显示简短来源名称，完整编号和文件信息放入“查看信息来源”。
4. 目录匹配只用于核对药品身份，不得作为用法用量、禁忌、不良反应或疗效来源。
5. OCR结果与目录不一致时并排展示，不自动用目录值覆盖用户材料。
6. 找到多个同名产品时必须让用户按批准文号、规格和企业确认。
7. `material_value`只能来自用户上传材料或人工确认，`catalog_value`只能来自对应目录或官方记录。
8. `display_value`通常使用材料值；目录值不得静默覆盖材料值，冲突时必须同时保留两个值。
9. 目录不得补充材料中没有的剂量、频次、禁忌、不良反应、注意事项或疗效。
10. 药名、规格、批准文号和生产企业等关键字段的`sources`不得无故为空。
11. `SRC-002`匹配结果不得输出“属于医保报销”“可以报销”或报销比例结论；如需核对最新编码，引导用户访问国家医保信息业务编码标准数据库：`https://code.nhsa.gov.cn/`。

## 五、来源类型代码

| 来源代码 | 来源名称 | 对应内容 | 老人页面简称 |
|---|---|---|---|
| `USER_PACKAGE` | 用户上传的药盒或药瓶 | 药名、规格、批准文号、企业、批号和日期等OCR内容 | 来自您上传的药盒 |
| `USER_INSTRUCTION` | 用户上传的药品说明书 | 成分、用途、用法用量、禁忌、注意事项、不良反应和贮藏等 | 来自您上传的说明书 |
| `USER_PRESCRIPTION` | 用户上传的医院处方 | 药品、规格、医生记录的用法用量 | 来自您上传的处方 |
| `USER_MEDICATION_LIST` | 用户上传的门诊或出院用药清单 | 多药名称、规格、用法和时间 | 来自您上传的用药清单 |
| `MEDICAL_INSURANCE_CATALOG` | 医保药品编码数据 | 注册名称、商品名称、剂型、规格、企业、批准文号、药品代码和本位码 | 来自医保药品编码数据 |
| `ESSENTIAL_MEDICINES_LIST` | 国家基本药物目录 | 基本药物名称、剂型、规格及范围参考 | 来自国家基本药物目录 |
| `NMPA_REFERENCE` | 国家药监局公开信息 | 药品身份、批准信息的修订参考 | 参照国家药监局公开信息 |
| `MANUAL_CONFIRMATION` | 用户或人工确认 | 用户确认的药名、规格或候选产品 | 已由您确认 |

## 六、来源编号格式

### 1. 用户材料

```text
MAT-{材料ID}-{图片序号}
```

示例：

```text
MAT-M20260717001-IMG03
```

说明书页码能够识别时增加页码：

```text
MAT-M20260717001-IMG03-P02
```

### 2. 医保药品编码数据

```text
SRC-002-{医保药品代码}
```

示例：

```text
SRC-002-XA10BJB219B002010180532
```

若前端只收到批准文号而没有医保药品代码，可以暂用：

```text
SRC-002-{批准文号}
```

### 3. 国家基本药物目录

```text
SRC-001-{目录品种名称}-{页码}
```

### 4. 国家药监局修订参考

```text
REF-001-{批准文号}-{查询日期}
```

查询日期使用`YYYYMMDD`，例如：

```text
REF-001-国药准字H20067255-20260717
```

## 七、前端统一JSON格式

每个可展示字段只使用`material_value`、`catalog_value`、`display_value`、`status`、`sources`和`missing_message`结构，不得返回旧的`value/source/status`结构，也不得只返回没有来源的纯文本。

```json
{
  "field": "drug_name",
  "label": "药品名称",
  "material_value": "示例药品名称",
  "catalog_value": "示例药品名称",
  "display_value": "示例药品名称",
  "status": "confirmed",
  "sources": [
    {
      "source_id": "MAT-M20260717001-IMG01",
      "source_type": "USER_PACKAGE",
      "short_name": "来自您上传的药盒",
      "location": "图片1，药品名称区域"
    },
    {
      "source_id": "SRC-002-XA10BJB219B002010180532",
      "source_type": "MEDICAL_INSURANCE_CATALOG",
      "short_name": "来自医保药品编码数据",
      "document_name": "医保药品（西药、中成药）编码",
      "location": "医保药品代码 XA10BJB219B002010180532",
      "updated_at": null
    }
  ],
  "missing_message": null
}
```

### 状态值

| 状态代码 | 含义 | 页面处理 |
|---|---|---|
| `confirmed` | 用户材料与目录信息一致，或已由用户确认 | 正常展示 |
| `material_only` | 只在用户材料中出现，尚未与目录对应 | 标注“来自您上传的材料” |
| `catalog_only` | 只在目录候选中出现，用户材料没有明确显示 | 不自动当作用户材料内容 |
| `conflict` | 用户材料与目录不一致 | 显示“有信息要确认” |
| `unclear` | 图片模糊或OCR置信度低 | 提示重新拍照 |
| `missing` | 当前材料中未出现 | 显示缺失文案或隐藏非必要字段 |

## 九、页面展示格式

### 1. 首屏简短引用

首屏字段下方最多显示一个来源标签：

```text
药品名称
苯磺酸氨氯地平片
来源：您上传的药盒，并已与目录记录对应
```

说明书内容：

```text
这个药是做什么的
{通俗解释}
来源：您上传的说明书
```

首屏不得显示长文件名、医保药品代码、原始CSV文件名或网页链接。

### 2. “查看信息来源”弹层

弹层按来源分组：

```text
信息来源

您上传的材料
• 药盒图片1：药品名称、规格、批准文号
• 说明书图片3第2页：适应症或功能主治

目录核对
• 医保药品（西药、中成药）编码
• 药品代码：{医保药品代码}
• 批准文号：{批准文号}
• 数据状态：{源数据状态}

核对说明
医保药品编码数据用于核对药品身份，不代替说明书和医生、药师意见，也不代表该药属于医保报销范围、可以报销或具有特定报销比例。
```

### 3. 冲突展示

```text
有些信息还要确认

药盒上识别到：{material_value}
目录中记录为：{catalog_value}

请对照药盒上的批准文号和规格。
```

按钮：

- 主按钮：`是这个药`
- 次按钮：`不是这个药`
- 图片模糊时：`重新拍照`

不得使用“假药”“目录错误”“识别失败”等确定性或技术性表达。

## 十、字段与引用来源对应表

| 页面字段 | 第一来源 | 第二来源 | 前端规则 |
|---|---|---|---|
| 药品名称 | 用户药盒OCR | 医保药品编码数据 | OCR为确认对象，编码数据为核对值 |
| 商品名称 | 用户药盒OCR | 医保药品编码数据 | 没有商品名时不显示 |
| 剂型 | 用户药盒或说明书 | 医保药品编码数据 | 优先显示材料值；不一致时并排展示 |
| 规格 | 用户药盒或说明书 | 医保药品编码数据 | 不一致时必须确认 |
| 批准文号 | 用户药盒或说明书 | 医保药品编码数据/NMPA参考 | 优先作为具体产品匹配键 |
| 生产企业 | 用户药盒或说明书 | 医保药品编码数据 | 优先显示材料值；编码数据只用于核对 |
| 用法用量 | 用户处方、清单或说明书 | 无 | 目录不得补充用法用量 |
| 适应症或功能主治 | 用户说明书 | 无 | 只解释用户上传的说明书内容 |
| 禁忌 | 用户说明书 | 无 | 材料缺页时提示可能不完整 |
| 注意事项 | 用户说明书 | 无 | 不从目录推断 |
| 不良反应 | 用户说明书 | 无 | 不从目录推断 |
| 贮藏 | 用户说明书或药盒 | 无 | 只显示明确识别内容 |
| 医保药品代码 | 医保药品编码数据 | 无 | 仅在编号详情中显示 |
| 药品本位码 | 医保药品编码数据 | 无 | 仅在编号详情中显示 |
| 数据状态 | 医保药品编码数据 | NMPA参考 | 不显示为“批准状态”“报销状态”或“真假结论” |

## 十一、多来源显示规则

### 一致

```text
status: confirmed
页面：药品信息已对上
```

### 用户材料有值、目录无值

```text
status: material_only
页面：来自您上传的材料，目录中暂未找到对应字段
```

### 用户材料无值、目录有值

```text
status: catalog_only
页面：不得自动补入“材料上写的是”模块
```

### 不一致

```text
status: conflict
页面：同时显示两个值，并要求用户确认
```

### 多个候选产品

每张候选卡只显示：

```text
药品名称
商品名称（有时显示）
规格
生产企业
批准文号
```

聚合CSV中的`|`分隔内容必须先拆分成具体候选记录，不得原样显示给用户。

## 十二、来源详情字段

前端来源对象统一使用：

```text
source_id          来源唯一编号
source_type        来源类型代码
short_name         老人页面简称
document_name      文件或数据集名称
publisher          发布或提供单位
location           图片编号、页码、章节或数据记录
source_url         原始公开链接；没有则为空
source_file        项目内来源文件；普通页面不显示
published_at       发布日期；没有则为空
updated_at         数据更新时间；没有则为空
retrieved_at       项目获取日期
verification_note  核对说明
```

空值使用`null`，不得使用“未知来源”填充。
