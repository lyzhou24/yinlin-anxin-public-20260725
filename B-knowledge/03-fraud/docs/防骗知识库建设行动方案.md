# 防骗知识库建设行动方案

## 一、建设目标

负责人B按照“官方资料定规则、原始话术定证据、完整上下文定风险、正规渠道定行动”的原则，建设面向老年人及家属的健康消费与常见养老骗局知识库，并完成从来源登记、规则拆分、案例结构化到Coze导入测试的闭环。

第一版优先覆盖药品、保健品、健康讲座、私域直播、异常付款和远程控制；扩展覆盖养老服务、养老投资、以房养老、代办养老保险、养老帮扶、收藏品回购和冒充官方等常见涉老骗局。

## 二、核心原则

1. 以“原始话术或行为证据＋单一风险类型”为最小知识单元。
2. 原始话术、风险判断和一般防范规则分开保存，不把概括写成用户原话。
3. 同一材料存在多类风险时拆行，不将多个风险压在一行。
4. 核心规则优先使用国家机关、司法机关、监管部门和地方政府官方资料。
5. 正规媒体仅用于补充新型骗局表达；自媒体和个人经历不得单独支撑正式规则。
6. 不直接认定个人或机构实施诈骗、违法或犯罪；司法和行政结论只用于对应已公布案例。
7. 不根据知识库自行诊断、推荐药品、停药、换药或调整剂量。
8. 材料信息不足时返回“需要进一步核验”，不得输出“绝对安全”。

## 三、来源优先级

### A级

- 最高人民法院、最高人民检察院、公安部；
- 市场监管总局、国家药监局、金融监管总局；
- 民政部、人力资源社会保障部门、医保部门；
- 国家级官方反诈和举报平台。

### B级

- 地方公安、法院、检察院；
- 地方市场监管、民政、医保和人社部门；
- 地方人民政府门户网站。

### C级

- 正规媒体对官方案件、行政处罚或风险提示的报道。

C级资料只用于发现话术和补充案例过程；涉及产品违法、犯罪定性和处罚结论时必须回溯到A/B级来源。

## 四、执行步骤

### 步骤1：登记来源

每份资料先登记到`sources/防骗资料来源清单.csv`，记录唯一来源编号、标题、机构、日期、链接、适用范围和核验状态。来源编号统一使用`FRAUD-SRC-###`。

### 步骤2：保存原始材料

优先保存网页HTML、原始PDF或官方附件。原始文件不得修改；清洗稿另存到`cases/data`或正式主表。动态网页无法完整保存时，至少记录链接、获取日期和页面标题。

### 步骤3：提取原始证据

只提取能够支持身份、宣传、交易或情绪操控判断的短句。不得把编辑后的结论放入“原始话术”；无法确认原句时不进入正式主表。

### 步骤4：拆分风险

同一句话出现多种风险时复制原始话术并分行记录。例如“吃完可以停药，今天转个人微信，不要告诉孩子”至少拆成宣传、交易和情绪操控三行。

### 步骤5：确定风险等级

- 绿色：完整上下文中暂未发现明显风险；
- 黄色：身份、资质、宣传、合同或付款信息不清，需要核验；
- 红色：出现验证码、远程控制、私人转账、诱导自行停药、冒充官方要求付款、恐吓、隐瞒家属或已付款失联等直接高危行为。

不能因单独出现“免费”“专家”“限时”“保健”等词判为红色。

### 步骤6：写行动和核验

“建议停止操作”先写当前不应继续做的事；“核验方法”写明核验对象、官方渠道和需要核对的字段；“证据保存”列出截图、账号、订单、合同、收款方、付款流水、宣传承诺和退款规则。

### 步骤7：制作案例知识卡

案例卡只保留诈骗链条的可复用结构，不强调无助于检索的姓名和具体金额。每张卡必须区分官方已认定事实、可复用风险信号和系统输出限制。

### 步骤8：生成Coze导入包

正式主表通过人工复核后，机械复制为`import/Coze防骗知识库导入.csv`。导入包不得领先于正式主表，也不得在导入副本中单独修订内容。

### 步骤9：检索与安全测试

至少覆盖明显红色、隐蔽表达、正常材料、信息不足、OCR错字和多风险组合。每条测试明确必须出现和禁止出现内容。

## 五、人工复核清单

- [ ] 原始话术可在来源中定位；
- [ ] 每行只包含一种风险类型；
- [ ] 风险等级符合三级标准；
- [ ] 风险原因结合上下文，不只解释关键词；
- [ ] 停止操作是可执行短句；
- [ ] 核验方法包含具体对象和正规渠道；
- [ ] 来源编号可在来源清单中找到；
- [ ] 没有诊断、荐药、停药、换药或改量建议；
- [ ] 没有无证据认定诈骗或违法；
- [ ] 绿色结果没有表述为“绝对安全”。

## 六、维护频率

- 每季度检查链接、举报渠道和新增典型案例；
- 新型骗局先进入待复核区，获得A/B级来源后再进入主表；
- Coze测试出现漏召回时先补同义词，不能直接降低红色风险门槛；
- 政策、平台或举报渠道变化时同步更新来源清单、知识主表和测试集。
