# web-sources 网页测试素材说明

本目录保存从公开网页收集并整理的图片材料，用于模拟用户上传药盒、说明书、保健食品包装、普通食品页面和药品追溯查询结果。它是测试输入素材库，不是药品或保健食品官方知识库。

> 整理日期：2026-07-18。目前共有49张正式图片：药品包装21张、说明书8张、药品追溯7张、保健食品11张、普通食品对照2张。

## 一、目录结构

```text
web-sources/
├─ README.md
├─ medicine-packages/        药盒、包装侧面、包装背面、铝塑板等（21张）
├─ instructions/             说明书实拍或说明书图片（8张）
├─ trace-code/               国家医保局药品追溯操作与结果截图（7张）
├─ health-food/
│  ├─ README.md              保健食品样本明细与使用边界
│  ├─ qualified/             可作为完整包装输入的核心样本（2张）
│  └─ reference/             警示语、科普、注册证书和包装侧面参考（9张）
├─ food-comparison/
│  ├─ README.md              普通食品对照样本说明
│  └─ FOOD-315-001_*.png     压片糖果商品页与说明信息（2张）
└─ .tmp315more/              网页提取临时数据，不属于正式交付和测试输入
```

原先整理的37条315价格网说明书文字已经合并到上级目录的`说明书OCR测试样本_真实87条_扰动51条.xlsx`，因此本目录当前重点保存网页图片及其来源说明。

## 二、各目录具体用途

### 1. `medicine-packages/`：药品包装图片

|---|---|---:|---|
| `WEB-MED-003` | 石药阿莫西林 | 1 | 单张正面包装、药名和规格识别 |
| `WEB-MED-004` | 仁济堂阿莫西林 | 5 | 同一药品多面包装归并、字段位置变化 |
| `WEB-MED-005` | 阿莫仙阿莫西林 | 2 | 包装背面与铝塑板配对 |
| `WEB-MED-006` | 布洛芬OTC包装 | 3 | OTC标识、药品包装与营销文字区分 |
| `WEB-MED-007` | 复方利血平氨苯蝶啶片 | 1 | 药盒和说明书同时出现时的材料拆分 |
| `WEB-MED-008` | 硝苯地平缓释片（Ⅱ） | 1 | 单药主图分类和字段提取 |
| `WEB-MED-009` | 泰诺林对乙酰氨基酚缓释片 | 3 | 正面与两个侧面归并 |
| `WEB-MED-010` | 尼美舒利颗粒 | 2 | 处方药包装、多图一致性 |
| `WEB-MED-011` | 布洛芬 | 3 | 同组多图和包装文字稳定性 |

适合测试：

- 是否正确分类为药品包装；
- 是否能从多张图片归并药名、规格、批准文号和生产企业；
- 是否保留每张图片的原始字段位置；
- 同药名不同厂家或不同规格是否会错误合并；
- 药盒、铝塑板和说明书是否会被错误识别成多个药品。

这些图片来自药品信息或销售网站，只能模拟用户上传材料。页面显示的信息不能直接写入`catalog_value`，也不能替代国家药监局或医保药品编码数据。

### 2. `instructions/`：真实说明书图片

共8张：

| 编号组 | 内容 | 图片数量 | 测试重点 |
|---|---|---:|---|
| `WEB-INSTR-001` | 华润三九感冒灵颗粒说明书 | 1 | 清晰说明书OCR、栏目识别 |
| `WEB-INSTR-002` | 散利痛说明书实拍 | 1 | 实拍图、小字号和版面分栏 |
| `WEB-INSTR-003` | 硝苯地平缓释片（Ⅱ）说明书 | 3 | 多页说明书排序和内容归并 |
| `WEB-INSTR-004` | 泰诺林对乙酰氨基酚缓释片说明书 | 1 | 单页完整说明书提取 |
| `WEB-INSTR-005` | 硝苯地平缓释片（Ⅱ）说明书正反面 | 2 | 正反面配对、重复字段去重 |

适合测试：

- OCR是否保留药品名称、规格、用法用量、禁忌、注意事项和警示语；
- 说明书正反面、多页或多栏文字是否按正确药品归并；
- 文字被折痕、印章、阴影或背景干扰时是否提示核对；
- 图片不完整时是否进入补充材料或重新上传状态；
- 是否避免把说明书中的剂量直接改写成对用户的个体用药建议。

说明书图片与Excel中的真实文字样本是两种不同测试入口：图片测试完整OCR链路，Excel的`text`字段测试“OCR已经完成后的文字处理链路”。

| 文件 | 页面含义 | 正确处理 |
|---|---|---|
| `WEB-TRACE-001_公众号入口.png` | 国家医保服务平台公众号入口 | 识别为官方查询入口，不是药品包装 |
| `WEB-TRACE-002_医保服务入口.png` | 医保服务菜单 | 引导进入药品追溯查询 |
| `WEB-TRACE-003_药品信息查询.png` | 药品追溯码查询页面 | 识别查询动作和输入位置 |
| `WEB-TRACE-004_未查询到销售信息.png` | 未查询到销售记录 | 只能说明当前未查到，不直接认定假药 |
| `WEB-TRACE-005_一次销售本人购买.png` | 一次销售且本人购买 | 展示查询结果，不等同于完成所有真实性核验 |

| `WEB-TRACE-007_两次以上销售.png` | 显示两次以上销售记录 | 提示进一步核验，不单凭截图判定真假 |

这一组用于测试“药品真实性核验流程”，可以触发`product_authenticity`相关核验信号，但不能因为出现异常页面就自动输出诈骗结论。截图只说明页面展示的查询状态，不能替代实物包装、批准文号、生产企业和追溯码的联合核验。

### 4. `health-food/`：保健食品包装和参考材料

共11张，分为核心输入和辅助参考。

`qualified/`中的2张健视佳包装图可作为用户上传材料，重点检查：

- 蓝帽标志；
- 注册号`国食健注G20140244`；
- 保健功能“缓解视疲劳”；
- 警示语“保健食品不是药物，不能代替药物治疗疾病”；
- 同一产品不同拍摄角度的字段一致性。

`reference/`中的9张图用于特定字段或比对：

- `HF-REF-001`只测警示语OCR；
- `HF-REF-002`只测市场监管总局查询入口；
- `HF-REF-003`、`HF-REF-004`用于保健功能和适宜人群规则；
- `HF-REF-005`—`HF-REF-008`用于侧面、批号、防伪、瓶装和盒装归并；
- `HF-REF-009`用于包装注册号与登记材料比对，不模拟用户上传包装。

保健食品样本不得进入药品说明书流程，不得返回`国药准字`或药品用法用量，也不得把“保健功能”改写为疾病治疗功效。详细清单见`health-food/README.md`。

### 5. `food-comparison/`：普通食品对照

共2张，均来自同一个压片糖果页面：

- `FOOD-315-001_酸枣仁茯苓百合GABA压片糖果_商品页.png`；
- `FOOD-315-001_酸枣仁茯苓百合GABA压片糖果_说明信息.png`。

正确分类是普通食品/压片糖果，不是药品，也不能因为网页标签写着“说明书”就当作药品说明书。批准信息`SC10636098210318`是食品生产许可证编号，不是药品批准文号，也不是保健食品注册或备案号。

该组重点验证：

- 页面栏目名称不能代替材料身份判断；
- 可以提取食品名称、配料、食用方法、限量和不适宜人群；
- 不返回药品剂量、药品批准文号或治疗功效；
- 可以提示“这是普通食品，不是药品”，但不能仅凭页面判断为假药。

详细标准见`food-comparison/README.md`。

## 三、编号规则

| 前缀 | 含义 | 使用位置 |
|---|---|---|
| `WEB-MED-` | 网页药品包装图片 | `medicine-packages/` |
| `WEB-INSTR-` | 网页或实拍说明书图片 | `instructions/` |
| `WEB-TRACE-` | 官方药品追溯操作和结果图 | `trace-code/` |
| `HF-PKG-` | 可作为完整保健食品包装输入的样本 | `health-food/qualified/` |
| `HF-REF-` | 保健食品规则、字段或登记参考图 | `health-food/reference/` |
| `FOOD-315-` | 315价格网普通食品对照样本 | `food-comparison/` |
| `315-MED-` | 已合并进Excel的说明书文字样本 | 上级说明书OCR工作簿 |

这些编号是测试素材编号，不是接口中的材料来源编号。工作流运行后如需返回`material_sources`，应另外生成本次上传材料的`MAT-...`编号，不能直接把`WEB-MED-...`或`315-MED-...`当作接口材料编号。

## 四、来源可信度与字段边界

| 来源类型 | 可以支持 | 不可以支持 |
|---|---|---|
| 用户材料模拟图/第三方商品页 | 材料中实际可见的药名、规格、文字和位置 | 官方目录值、真伪确认、医保报销资格 |
| 药品生产企业官网 | 对应页面公开说明书或产品信息 | 用户上传材料中未出现的字段 |
| 国家医保局追溯页面 | 查询入口、操作和页面结果含义 | 单凭截图确认药品一定真或一定假 |
| 市场监管部门科普页 | 保健食品识别规则和警示语含义 | 某个商品的最终注册状态，除非另查官方登记 |
| 销售网站 | 测试图片和页面可见字段 | 疗效、推荐购买、价格合理性和官方登记结论 |

任何网页来源都不得用于证明“属于医保报销范围”或“可以报销”。药品编码匹配只说明编码数据匹配，不代表医保报销资格。

## 五、推荐测试流程

### 图片到OCR的完整流程

1. 从一个子目录选择单张或同一编号组的多张图片。
2. 将文件作为用户上传材料进入材料分类节点。
3. 记录系统返回的材料类型和OCR原文。
4. 检查多图是否正确归并、图片顺序是否合理。
5. 对照图片逐字段核验药名、规格、批准信息、企业、警示语和位置。
6. 如图片模糊、字段遮挡或只有二维码，应停止后续Risk判断并提示重新上传或补充材料。
7. 将实际输出和失败原因保存到上级`outputs/`。

### 说明书文字处理流程

如果只测试OCR之后的文字处理，不需要重新识别这些图片，应直接使用：

`../../说明书OCR测试样本_真实87条_扰动51条.xlsx`

工作簿内：

- “真实说明书文字”用于正常提取和缺失边界；
- “扰动测试版本”用于字符混淆、断行、顺序变化和弱标点；
- `processing_boundary`用于判断系统是否越界补全。

## 六、每次测试必须记录

- 本地文件名或样本编号；
- 原始来源页面；
- 上传图片数量及顺序；
- 工作流和提示词版本；
- OCR原文；
- 材料分类结果；
- 提取字段和来源位置；
- 是否触发补充材料状态；
- 是否错误调用Risk接口；
- 实际结果、预期结果、错误类型和回归状态。

## 七、常见错误

- 把第三方商品页字段当作官方目录字段；
- 把普通食品页面的“说明书”标签当作药品说明书；
- 把保健功能改写成治疗疾病；
- 把包装规格当作一次用量；
- 多张说明书顺序错误或跨药品拼接；
- 图片不清晰时仍输出确定剂量或风险等级；
- 未查询到追溯记录就直接判断为假药；
- 把药品编码匹配解释为医保可以报销；
- 将测试文件编号冒充接口`MAT-...`材料来源编号。

## 八、版权、隐私和发布限制

1. 本目录网图仅用于内部OCR、分类和工作流测试。
2. 图片版权归原网站或原权利人所有，不默认获得公开再分发或商业使用授权。
3. 第三方商品页不得用于推荐购买、疗效或价格结论。
4. 正式对外交付测试集前，应再次核对来源和授权，无法确认的图片应替换为自拍、自制或明确开放使用的材料。
5. 不使用包含真实患者姓名、电话、地址、处方和订单信息的图片；如必须测试，应先脱敏。
6. 不修改真实厂家图片制造虚假批准文号或字段冲突；冲突测试应使用明确标注的虚构材料。

## 九、当前仍需补充的样本

- 批号、生产日期和有效期清晰特写；
- 批准文号反光、遮挡和局部裁剪版本；
- 严重失焦、过暗、过曝和运动模糊版本；
- 两种或三种不同药品的清晰合照；
- 同药名不同厂家、同批准文号不同规格的对照图；
- 只有二维码但没有可读包装字段的材料；
- 药盒字段与官方查询结果冲突的明确虚构样本；
- 虚构处方、用药清单和订单；
- 保健食品冒充药品并诱导停药的宣传材料。
