# 银龄安心 - 接口绑定说明3.0

> 版本：3.0  
> 更新日期：2026-07-18  
> 基于《接口绑定说明2.0》修订，原2.0文件保持不变。

## 3.0版本改动说明

1. Risk接口的每条`signals[]`增加`material_sources`和`knowledge_sources`，分别追溯用户材料位置与`FRAUD-SRC-xxx`知识依据。
2. 三级风险页面含义统一为：`green`“暂未发现明显风险”、`yellow`“有些信息需要进一步核实”、`red`“建议立即停止相关操作”；禁止把`green`显示为“安全”“放心购买”或“已经确认是真药”。
3. 家属简报规则与2.0保持一致：`red`自动生成家属简报；存在已授权且有效的家属联系方式时自动推送，无授权联系人时只生成并提示绑定，联系方式无效时记录失败；`green`和`yellow`由用户点击“生成家属简报”。
4. `SRC-002`页面简称统一为“来自医保药品编码数据”；编码匹配仅用于身份字段核对，不代表医保报销资格、是否可以报销或报销比例。
5. 明确`product_authenticity`只能由药品真实性核验规则或真实性核验流程生成，不得由防骗主表四类风险直接生成。
6. 药品引用对象统一补齐`missing_message`；非缺失字段返回`null`，缺失字段返回面向用户的提示文案。
7. 保留2.0的信息不足降级方案：`image_blurry`、`type_uncertain`和`qrcode_only`；这些情况不调用Risk接口、不返回风险结果，也不显示风险徽章。
8. Coze药品节点输出统一为`success → data → medicine`，使用`drug_name`、`specification`和`approval_number`等2.0接口字段，废止`medicine_fields.generic_name`和`plain_language_card`旧结构。
9. Risk输出以2.0字段为主体，新增并完整定义`material_sources`、`knowledge_sources`及其来源类型枚举；提示词不再返回接口未登记的冗余字段。
10. FamilyBrief统一使用2.0的`material_summary`、`material_type`、`product_or_person`、`payment_status`、`highest_risk`、`risk_categories`和`next_actions`等字段，并增加`generation_mode`、`recipient_status`、`push_channel`、`share_status`、`push_status`、`pushed_at`和`push_error`支持红色自动推送及失败处理。

## 一、通用约定

### 1.1 请求规范

| 项目 | 约定 |
|---|---|
| 协议 | HTTPS（生产）/ HTTP（本地开发） |
| 数据格式 | JSON |
| 编码 | UTF-8 |
| 认证方式 | 待定（建议：会话 Cookie 或 Token） |
| 图片上传 | 先上传到对象存储，返回 `file_url`，后续接口传 `file_url` |

### 1.2 通用返回结构

```json
{
  "success": true,
  "data": {},
  "error": null
}
```

失败时：

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "ocr_failed",
    "message": "未能识别文字，请尝试调整光线后重拍"
  }
}
```

> 以上为错误结构示例，`code` 和 `message` 的具体取值见下方《错误码与页面展示对照表》。

### 1.3 错误码与页面展示对照

| 错误码 | 触发场景 | 页面展示文案 | 跳转/操作 |
|---|---|---|---|
| `unsupported_format` | 上传非图片文件 | 文件格式不支持，请上传 JPG、PNG 格式的照片。 | 停留在上传页 |
| `file_too_large` | 单张图片超过 10MB | 文件过大，请上传不超过 10MB 的图片。 | 停留在上传页 |
| `image_blurry` | 清晰度检测得分低于阈值 | 照片不够清晰，建议对准材料重新拍摄。 | 返回 `/upload` |
| `ocr_failed` | 文字提取返回空或错误 | 未能识别文字，请尝试调整光线后重拍。 | 返回 `/upload` |
| `type_uncertain` | 无法自动判断材料类型 | 系统无法判断，请手动选择材料类型。 | 停留在 `/confirm` |
| `ai_failed` | 工作流超时或模型异常 | 分析暂时失败，请稍后再试。 | 重试或返回 `/` |
| `network_error` | 网络请求失败 | 网络连接失败，请检查网络后重试。 | 重试当前操作 |
| `approval_number_not_found` | 批准文号查不到 | 该批准文号暂未核验成功，建议通过正规渠道进一步查询。 | 停留在 `/medicine` |
| `approval_number_mismatch` | 批准文号对应其他药品 | 包装信息与官方备案不一致，建议暂停使用并咨询药师。 | 停留在 `/medicine` |
| `qrcode_only` | 图片只有二维码 | 检测到二维码，但缺少上下文信息，请补充上传完整材料。 | 返回 `/upload` |
| `save_failed` | 数据库写入失败 | 保存失败，结果仅在本次会话有效。 | 停留当前页 |
| `delete_failed` | 删除失败 | 删除失败，请稍后重试。 | 停留在 `/history` |

## 1.4 药品信息字段返回规则（引用格式）

药品结果页中的每个可展示字段，必须按《药品知识库引用格式.md》返回为一个**引用对象**，不得只返回纯文本字符串。C 在实现 `/api/medicine` 接口时，应按以下规则填充每个字段。

### 1.4.1 引用对象结构

每个字段统一返回：

```json
{
  "material_value": "用户材料中的原始值",
  "catalog_value": "目录/官方记录中的值",
  "display_value": "页面最终展示值",
  "status": "字段状态",
  "sources": [
    {
      "source_id": "MAT-M20260717001-IMG01",
      "source_type": "USER_PACKAGE",
      "short_name": "来自您上传的药盒",
      "location": "图片1，药品名称区域"
    }
  ],
  "missing_message": null
}
```

### 1.4.2 三个 value 字段的含义与填充规则

| 字段 | 含义 | C 的填充规则 | 前端如何使用 |
|---|---|---|---|
| `material_value` | 从用户上传材料中识别出的原始值 | OCR 或用户输入的内容，材料中没有则为 `null` | 作为用户材料侧的值展示，尤其在冲突时 |
| `catalog_value` | 从医保目录、基本药物目录、NMPA 等官方数据中查到的值 | 按批准文号/药名匹配到的官方记录，没有则为 `null` | 仅用于核对身份，不直接当作页面展示值 |
| `display_value` | 页面最终显示给用户的值 | 通常等于 `material_value`；当 `status` 为 `missing` 时为 `null` | 直接展示在页面上；冲突时前端会同时展示 `material_value` 和 `catalog_value` |

**核心规则**：目录值（`catalog_value`）只用于**核对药品身份**，不得自动覆盖或补充用户材料中没有的用法用量、禁忌、不良反应等信息。

### 1.4.3 状态值与填充示例

必须按以下状态返回，不得自行定义其他状态字符串。

#### `confirmed`：用户材料与目录一致

```json
{
  "material_value": "氨氯地平贝那普利片",
  "catalog_value": "氨氯地平贝那普利片",
  "display_value": "氨氯地平贝那普利片",
  "status": "confirmed",
  "sources": [
    { "source_id": "MAT-M20260717001-IMG01", "source_type": "USER_PACKAGE", "short_name": "来自您上传的药盒", "location": "图片1" },
    { "source_id": "SRC-002-国药准字H20090810", "source_type": "MEDICAL_INSURANCE_CATALOG", "short_name": "来自医保药品编码数据", "location": "医保药品编码记录" }
  ],
  "missing_message": null
}
```

#### `material_only`：只在用户材料中，目录中没有对应值

```json
{
  "material_value": "一次一片",
  "catalog_value": null,
  "display_value": "一次一片",
  "status": "material_only",
  "sources": [
    { "source_id": "MAT-M20260717001-IMG03-P02", "source_type": "USER_INSTRUCTION", "short_name": "来自您上传的说明书", "location": "图片3，第2页，用法用量章节" }
  ],
  "missing_message": null
}
```

#### `catalog_only`：只在目录中有，用户材料没有明确显示

```json
{
  "material_value": null,
  "catalog_value": "5mg",
  "display_value": null,
  "status": "catalog_only",
  "sources": [
    { "source_id": "SRC-002-国药准字H20090810", "source_type": "MEDICAL_INSURANCE_CATALOG", "short_name": "来自医保药品编码数据", "location": "医保药品编码记录" }
  ],
  "missing_message": null
}
```

前端处理：该字段**不自动展示为用户材料内容**，仅在「查看信息来源」中作为目录参考信息展示。

#### `conflict`：用户材料与目录不一致

```json
{
  "material_value": "5mg",
  "catalog_value": "10mg",
  "display_value": "5mg",
  "status": "conflict",
  "sources": [
    { "source_id": "MAT-M20260717001-IMG01", "source_type": "USER_PACKAGE", "short_name": "来自您上传的药盒", "location": "图片1，规格区域" },
    { "source_id": "SRC-002-国药准字H20090810", "source_type": "MEDICAL_INSURANCE_CATALOG", "short_name": "来自医保药品编码数据", "location": "医保药品编码记录" }
  ],
  "missing_message": null
}
```

前端处理：同时显示 `material_value` 和 `catalog_value`，并提示用户确认，不自动用目录值覆盖。

#### `unclear`：图片模糊或 OCR 置信度低

```json
{
  "material_value": "氨氯地??片",
  "catalog_value": null,
  "display_value": "氨氯地??片",
  "status": "unclear",
  "sources": [
    { "source_id": "MAT-M20260717001-IMG01", "source_type": "USER_PACKAGE", "short_name": "来自您上传的药盒", "location": "图片1，药品名称区域" }
  ],
  "missing_message": null
}
```

前端处理：提示用户重新拍照或手动输入。

#### `missing`：当前材料中未出现该字段

```json
{
  "material_value": null,
  "catalog_value": null,
  "display_value": null,
  "status": "missing",
  "sources": [],
  "missing_message": "当前材料中未明确用药时间。"
}
```

前端处理：显示 `missing_message`，不编造内容，不自动用目录补充。

### 1.4.4 来源类型代码

C 返回的 `source_type` 必须严格使用以下枚举值：

| 来源代码 | 来源名称 | 适用场景 |
|---|---|---|
| `USER_PACKAGE` | 用户上传的药盒或药瓶 | 药名、规格、批准文号、生产企业、批号等 |
| `USER_INSTRUCTION` | 用户上传的药品说明书 | 适应症、用法用量、禁忌、不良反应、贮藏等 |
| `USER_PRESCRIPTION` | 用户上传的医院处方 | 医生记录的药品、规格、用法用量 |
| `USER_MEDICATION_LIST` | 用户上传的门诊或出院用药清单 | 多药名称、规格、用法和时间 |
| `MEDICAL_INSURANCE_CATALOG` | 医保药品编码数据 | 身份核对字段（药名、规格、批准文号、企业等） |
| `ESSENTIAL_MEDICINES_LIST` | 国家基本药物目录 | 基本药物身份核对 |
| `NMPA_REFERENCE` | 国家药监局公开信息 | 批准信息修订参考 |
| `MANUAL_CONFIRMATION` | 用户或人工确认 | 用户手动确认的药名、规格或候选产品 |

> `MEDICAL_INSURANCE_CATALOG`页面简称统一为“来自医保药品编码数据”。编码匹配只用于核对药品身份字段，不代表该药属于医保报销范围、可以报销或具有特定报销比例。如需核对最新编码，可访问国家医保信息业务编码标准数据库：`https://code.nhsa.gov.cn/`。

### 1.4.5 来源编号格式

| 来源类型 | 编号格式 | 示例 |
|---|---|---|
| 用户材料 | `MAT-{材料ID}-{图片序号}` | `MAT-M20260717001-IMG01` |
| 用户材料（说明书页码） | `MAT-{材料ID}-{图片序号}-P{页码}` | `MAT-M20260717001-IMG03-P02` |
| 医保药品编码数据 | `SRC-002-{医保药品代码}` 或 `SRC-002-{批准文号}` | `SRC-002-XA10BJB219B002010180532` |
| 国家基本药物目录 | `SRC-001-{目录品种名称}-{页码}` | `SRC-001-苯磺酸氨氯地平片-12` |
| 国家药监局参考 | `REF-001-{批准文号}-{YYYYMMDD}` | `REF-001-国药准字H20067255-20260717` |

## 二、按页面接口约定

### 2.1 首页 `/`

- **用户目标**：了解产品功能，快速进入上传流程或查看历史/简报。
- **输入**：无。
- **输出**：静态页面。
- **接口**：无需接口。
- **主要按钮**：
  - 「拍照或上传材料」→ `/upload`
  - 「请家里人一起看」→ `/family`
  - 「查看历史记录」→ `/history`

---

### 2.2 统一上传页 `/upload`

#### 2.2.1 用户目标

将药盒、说明书、处方、宣传材料、聊天截图、付款凭证等拍照上传。

#### 2.2.2 输入

- 用户拍摄或从相册选择图片（JPG/PNG，单张 ≤ 10MB）。

#### 2.2.3 前端行为

1. 选择图片后本地预览。
2. 点击「开始识别」后，先调用隐私检测接口。
3. 检测到敏感信息后弹出分支按钮。
4. 用户确认后继续进入预处理流程（上传 → 清晰度 → 隐私复核 → OCR → 图片理解）。

#### 2.2.4 接口 1：隐私信息检测

- **调用时机**：用户点击「开始识别」后。
- **请求**：

```json
POST /api/upload/privacy-check
{
  "files": ["file_url_1", "file_url_2"]
}
```

- **期望返回样例 1：未检测到隐私信息**：

```json
{
  "success": true,
  "data": {
    "has_sensitive_info": false,
    "sensitive_regions": []
  }
}
```

- **期望返回样例 2：检测到隐私信息**：

```json
{
  "success": true,
  "data": {
    "has_sensitive_info": true,
    "sensitive_regions": [
      { "file_url": "file_url_1", "type": "id_card", "bbox": [10, 20, 100, 80] }
    ]
  }
}
```

- **字段说明**：

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `has_sensitive_info` | boolean | 是否检测到敏感信息 | `true`：检测到；`false`：未检测到 |
| `sensitive_regions` | array | 检测到的敏感信息区域列表 | 无敏感信息时为空数组 `[]` |
| `sensitive_regions[].file_url` | string | 哪张上传图片包含敏感信息 | `"file_url_1"` |
| `sensitive_regions[].type` | string | 敏感信息类型 | `id_card`（身份证）、`phone`（手机号）、`address`（地址）、`bank_card`（银行卡）、`name`（姓名）、`medical_record_no`（病历号）等 |
| `sensitive_regions[].bbox` | array | 敏感区域在图片中的位置，格式为 `[x, y, width, height]` | `[10, 20, 100, 80]` 表示：左上角横坐标 10、纵坐标 20，宽度 100，高度 80 |

- **页面展示**：
  - `has_sensitive_info: true`：显示黄色警告框，提供「重新上传」「我已确认，继续识别」「取消上传」三个按钮。
  - `has_sensitive_info: false`：不弹警告框，直接进入后续预处理流程（清晰度检测 → OCR → 图片理解）。

#### 2.2.5 接口 2：材料识别与分类

- **对应类型**：`Material`（详见 `组件清单.md` 四、核心数据类型）

- **调用时机**：用户确认隐私后。
- **请求**：

```json
POST /api/upload/analyze
{
  "files": ["file_url_1"]
}
```

- **期望返回样例**：

```json
{
  "success": true,
  "data": {
    "material_id": "mat_001",
    "file_url": "file_url_1",
    "material_type": "medicine_leaflet",
    "confidence": 0.92,
    "quality": "good",
    "ocr_text": "【药品名称】氨氯地平贝那普利片...",
    "missing_fields": [],
    "route": "medicine",
    "authenticity_flags": {
      "authenticity_level": "needs_verification",
      "authenticity_level_label": "需要核验",
      "risk_signals": [
        "批准文号格式异常"
      ],
      "verification_suggestions": [
        "建议通过正规渠道进一步核验"
      ]
    }
  }
}
```

- **字段说明**：

| 字段 | 类型 | 含义 | 可选值/示例 |
|---|---|---|---|
| `material_id` | string | 材料唯一标识 | `mat_001` |
| `file_url` | string | 上传图片的访问地址 | `file_url_1` |
| `material_type` | string | 材料类型 | `regular_medicine`（正规药品）、`medicine_leaflet`（药品说明书）、`hospital_prescription`（医院处方）、`multiple_medicines`（多种药品）、`health_supplement`（保健食品）、`ordinary_food`（普通食品）、`medical_device`（医疗器械）、`health_promotion`（健康宣传材料）、`sales_chat`（推销聊天记录）、`payment_proof`（订单或付款凭证）、`unknown`（暂时无法判断） |
| `confidence` | number | 分类置信度，范围 0-1 | `0.92` |
| `quality` | string | 图片质量 | `good`（清晰）、`fair`（一般）、`poor`（模糊） |
| `ocr_text` | string | OCR 提取的文字内容 | `【药品名称】氨氯地平贝那普利片...` |
| `missing_fields` | array | 需要补充的信息字段 | 无缺失时为空数组 `[]` |
| `route` | string | 分析路由 | `medicine`（药品解读）、`fraud`（防骗分析）、`compare`（对照分析）、`evidence`（证据整理）、`multi_medicine`（多药品）、`manual_confirm`（人工确认） |
| `authenticity_flags` | object / null | 药品真实性风险初筛结果，由 WF-1 基于 OCR 和视觉信息生成，仅用于风险提示，不代表最终假药判定。非药品材料时为 `null` | 见下方子字段说明 |
| `authenticity_flags.authenticity_level` | string | 风险等级 | `likely_authentic`（未发现明显异常）、`needs_verification`（存在异常，需要进一步核验）、`suspected_counterfeit`（疑似仿冒风险）、`not_applicable`（非药品材料，不进行真实性判断） |
| `authenticity_flags.authenticity_level_label` | string | 前端展示文本 | `需要核验` |
| `authenticity_flags.risk_signals` | array | 检测到的风险信号 | `["批准文号格式异常"]` |
| `authenticity_flags.verification_suggestions` | array | 后续核验建议 | `["建议通过正规渠道进一步核验"]` |

|---|---|---|---|
| `source_id` | string | 是 | 用户材料编号，必须使用`MAT-...` |
| `source_type` | string | 是 | 用户材料来源类型 |
| `short_name` | string | 是 | 页面显示的简短来源名称 |
| `location` | string | 是 | 图片编号及证据所在区域或页码 |

Risk材料来源类型：

| `source_type` | 含义 | 页面简称示例 |
|---|---|---|
| `USER_PACKAGE` | 用户上传的药盒或药瓶 | 来自您上传的药盒 |
| `USER_INSTRUCTION` | 用户上传的说明书 | 来自您上传的说明书 |
| `USER_PROMOTION` | 用户上传的宣传单、海报或直播截图 | 来自您上传的宣传材料 |
| `USER_CHAT` | 用户上传的聊天记录 | 来自您上传的聊天记录 |
| `USER_PAYMENT` | 用户上传的付款或转账材料 | 来自您上传的付款材料 |
| `USER_ORDER_RECEIPT` | 用户上传的订单、合同、发票或收据 | 来自您上传的订单或凭证 |

##### Risk知识来源对象

`knowledge_sources[]`必须包含以下字段：

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `source_id` | string | 是 | 知识依据编号；正式防骗或真实性结论使用`FRAUD-SRC-xxx` |
| `source_type` | string | 是 | 知识来源类型 |
| `short_name` | string | 是 | 页面显示的简短依据名称 |

Risk知识来源类型：

| `source_type` | 含义 | 生成边界 |
|---|---|---|
| `ANTI_FRAUD_RULE` | 防骗知识库规则依据 | 用于`identity`、`claim`、`transaction`和`emotion` |
| `MEDICINE_AUTHENTICITY_RULE` | 药品真实性核验依据 | 仅用于真实性核验流程生成的`product_authenticity` |

编号不得混用：`MAT-...`只放入`material_sources`；`FRAUD-SRC-...`只放入`knowledge_sources`；药品字段的`SRC-001`、`SRC-002`和`REF-001`只放入Medicine字段的`sources`。

#### 2.5.4 页面展示要求

- 红色风险：顶部显示不可折叠的「立即行动」横幅（先别付款 / 不要提供验证码 / 不要停掉现在吃的药 / 请让家里人一起看）。
- 关键风险证据最多展示 3 条。
- 详细风险分析按类别展开：身份风险、宣传风险、交易风险、情绪操控风险、产品真实性风险。
- 产品真实性风险（`product_authenticity`）展示内容：
  - 包装异常
  - 批准文号异常
  - 产品信息不一致
  - 疑似仿冒风险
  - 对应 `stop_action`：不要继续购买或使用来源不明药品。

> `product_authenticity`只能由药品真实性核验规则或真实性核验流程命中后生成，用于包装、批准文号、药名、持有人、生产企业、规格、批号、有效期或追溯信息核验；不得由防骗主表的身份、宣传、交易或情绪操控规则直接生成。

#### 2.5.5 按钮规则

| 风险等级 | 「生成家属简报」按钮 |
|---|---|
| `green` / `yellow` | 显示，由用户主动生成 |
| `red` | 不显示；自动生成简报，并按实际状态显示“已推送”“请先绑定家属联系人”或“推送失败，请检查联系方式” |

红色风险自动生成家属简报；只有存在已授权且有效的家属联系方式时才自动推送。绿色和黄色仍由用户主动决定是否生成和分享。

| `doctor_questions_count` | number | 问医生清单中的问题数量 | `2` |

#### 2.6.4 自动推送状态约束

`push_status`和`share_status`必须按下表组合，不得返回互相矛盾的状态：

| 场景 | `recipient_status` | `push_status` | `share_status` | 页面文案 |
|---|---|---|---|---|
| 红色，等待推送 | `authorized` | `pending` | `push_pending` | 红色风险，家属简报正在推送 |
| 红色，推送成功 | `authorized` | `sent` | `auto_pushed` | 红色风险，简报已自动生成并推送 |
| 红色，推送失败或联系方式无效 | `invalid` | `failed` | `push_failed` | 简报已生成，但推送失败，请检查家属联系方式 |
| 红色，没有授权联系人 | `contact_missing` | `contact_missing` | `not_pushed` | 简报已生成，请先绑定家属联系人 |
| 绿色或黄色用户主动生成 | `not_applicable` | `not_applicable` | `draft_not_shared` | 简报已生成，由用户决定是否分享 |

只有`push_status: "sent"`时，`pushed_at`才可填写时间且`push_error`必须为`null`；其他状态下`pushed_at`为`null`。`failed`时必须填写`push_error`。

#### 2.6.5 红色风险自动推送触发流程

```text
Risk工作流完成并返回risk_level=red
→ 自动生成FamilyBrief
→ 查询用户已授权的家属联系人
→ 无联系人：写入contact_missing，不发送，结果页提示绑定
→ 联系方式无效：写入failed和push_error，结果页提示检查联系方式
→ 联系人有效：按已配置渠道执行推送
→ 回写push_status、share_status、pushed_at和push_error
→ 结果页按实际状态展示，不得在失败时显示“已推送”
```

建议由成员C在Risk工作流完成后触发内部自动推送动作；前端不得通过伪造`push_status`直接显示成功。

内部触发接口建议：

```json
POST /api/family-brief/auto-push
{
  "material_id": "mat_001"
}
```

该接口只能由服务端或工作流在已确认`risk_level=red`后调用。接收人从用户已授权的家属联系人配置中读取，前端不得在请求中临时传入任意收件人。接口返回更新后的FamilyBrief推送状态字段。接口路径、实际推送渠道和重试策略由成员A、C在开发前最终确认。

#### 2.6.6 按钮

- 转发给家人（调用系统分享或复制文本）
- 导出图片
- 打印
- 返回

## 五、特殊说明

1. 所有返回 `risk_level` 的接口，取值限定为 `green` / `yellow` / `red`。
2. 药品页和防骗页在`green`、`yellow`下显示「生成家属简报」按钮；`red`不显示按钮，系统自动生成家属简报，并仅在存在已授权且有效的家属联系方式时自动推送。
3. 家属简报的 `payment_amount`、`payment_account`、`personal_data_exposed` 等敏感字段，在未授权时不应展示具体内容，可返回「暂未确认」或空数组。
4. 历史记录支持分页（后续可扩展 `page` / `page_size` 参数）。
