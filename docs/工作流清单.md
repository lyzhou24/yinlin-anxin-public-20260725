## WF-1：材料预处理与安全分析

### 目标

用户上传药盒、说明书、宣传单、聊天截图等图片后，完成文件校验、图片清晰度判断、OCR 文字提取、图片内容理解、材料分类、隐私信息检测、仿冒药初筛和路由判断，输出 Material 对象。

### 部署信息

- **状态**：✅ 已完成，已联调通过
- **Coze Workflow URL**：`https://wxzr85dnjt.coze.site/run`
- **调用方式**：`POST` + `Authorization: Bearer <COZE_TOKEN>` + `Content-Type: application/json`
- **Next.js API 代理**：`POST /api/analyze`（`src/app/api/analyze/route.ts`）

### 输入

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file_url` | string | 是 | 对象存储中的图片公网地址（S3 签名 URL） |

### 输出

```json
{
  "material_json": {
    "material_id": "string",
    "file_url": "string",
    "material_type": "string",
    "type_label": "string",
    "confidence": "number",
    "confidence_level": "string",
    "quality": "object",
    "ocr_text": "string",
    "image_description": "string",
    "missing_fields": [],
    "route": "string",
    "classification_reason": "string",
    "sensitive_info_detected": {},
    "authenticity_flags": {}
  },
  "run_id": "string"
}
```

关键字段：
- `material_type`：材料分类标签（11 种之一）
- `confidence` / `confidence_level`：分类置信度及等级
- `ocr_text`：OCR 提取的全部文字
- `image_description`：图片视觉特征描述
- `sensitive_info_detected`：隐私信息检测结果（是否包含敏感信息、类型、位置）
- `authenticity_flags`：仿冒药初筛结果（仅药品类材料，含初步判断和判断依据）
- `route`：路由方向（"medicine" / "fraud" / "manual_confirm"）
- `run_id`：Coze 运行 ID，用于追溯

### 节点流程

```
Start (file_url)
  │
  ▼
N1 文件校验 (Code)
  │ 检查 file_url 是否为空、格式是否合法
  ├─ 不合法 → 错误出口
  │
  ▼
N2 图片清晰度评估 + OCR (LLM视觉)
  │ 判断清晰度，提取文字，模糊处标注 [无法识别]
  ├─ quality=poor → BLURRY_IMAGE 错误
  ├─ ocr_text 为空 → OCR_FAILED 错误
  │
  ▼
N3 图片内容理解 (LLM视觉)
  │ 描述材料形态、视觉特征、关键实体
  │
  ▼
N4 材料分类 (LLM文本)
  │ 根据 OCR + 视觉特征判断 material_type
  │ 输出 confidence + classification_reason
  │
  ▼
N5 隐私信息检测 (LLM视觉)
  │ 检测身份证号、银行卡号、验证码、地址、电话等
  │ 输出 sensitive_info_detected
  │
  ▼
N6 仿冒药初筛 (LLM文本, 条件执行)
  │ 仅药品类材料执行
  │ 检查批准文号格式、包装视觉特征
  │ 输出 authenticity_flags
  │
  ▼
N7 路由决策 (Code)
  │ 根据 material_type + confidence 决定 route
  │ confidence < 0.5 → manual_confirm
  │
  ▼
N8 输出聚合 (Code)
  │ 生成 material_id，组装 Material v2 JSON
  │
  ▼
End (material_json + run_id)
```

### 路由规则

| material_type | type_label | route |
|---------------|-----------|-------|
| `regular_medicine` | 正规药品 | medicine |
| `medicine_leaflet` | 药品说明书 | medicine |
| `hospital_prescription` | 医院处方 | medicine |
| `multiple_medicines` | 多种药品 | medicine |
| `health_supplement` | 保健食品 | fraud |
| `ordinary_food` | 普通食品 | fraud |
| `medical_device` | 医疗器械 | fraud |
| `health_promotion` | 健康宣传材料 | fraud |
| `sales_chat` | 推销聊天记录 | fraud |
| `payment_proof` | 订单或付款凭证 | fraud |
| `unknown` | 暂时无法判断 | manual_confirm |

**特殊规则**：当 `confidence < 0.5` 时，无论 `material_type` 是什么，`route` 强制为 `manual_confirm`。

### 仿冒药初筛逻辑

**触发条件**：仅当 material_type 为药品类（regular_medicine / medicine_leaflet / hospital_prescription / multiple_medicines）时执行。非药品类输出 `not_applicable`。

| 条件 | authenticity_level |
|------|-------------------|
| 批准文号格式正确 + 无视觉异常 | likely_authentic |
| 批准文号格式存疑 / 包装有轻微异常 | needs_verification |
| 无批准文号 / 格式严重错误 / 药名疑似仿冒 / 厂家信息缺失 | suspected_counterfeit |
| 非药品类材料 | not_applicable |

**重要边界**：
- WF-1 只做 OCR + 视觉层面的初步筛查，**不查知识库**
- `suspected_counterfeit` 不等于"这是假药"，仅表示"存在疑似仿冒特征，需专业核验"
- 深度核验由 WF-2 结合知识库完成

### 异常处理

| 异常场景 | WF-1 行为 | 前端处理 |
|---------|----------|---------|
| 图片太模糊 | 返回错误（BLURRY_IMAGE） | 提示重新拍摄 |
| OCR 无结果 | 返回错误（OCR_FAILED） | 提示调整光线重试 |
| 分类失败 | 返回错误（CLASSIFICATION_FAILED） | 跳转确认页手动选择 |
| 检测到敏感信息 | 正常返回 Material，sensitive_info_detected.has_sensitive_info=true | 前端弹出确认对话框 |
| 疑似仿冒药 | 正常返回 Material，authenticity_flags.level=suspected_counterfeit | 确认页/药品页展示红色警示 |
| Coze 平台不可用 | Next.js API 返回 502 + COZE_API_ERROR | 提示稍后重试 |
| COZE_TOKEN 未配置 | Next.js API 返回 500 + COZE_TOKEN_MISSING | 提示配置异常 |

| 测试场景 | 输入 | 预期结果 | 实际结果 |
|---------|------|---------|---------|
| 正常药品说明书 | 药品说明书图片 | material_type=medicine_leaflet, route=medicine | ✅ 通过 |
| 推销聊天截图 | 微信聊天图片 | material_type=sales_chat, route=fraud | ✅ 通过 |

无。分类规则、隐私检测规则、仿冒药初筛规则均写在 LLM 提示词中，不依赖外部知识库。深度核验由 WF-2 调用知识库完成。

## WF-2：药品说明解读

### 目标

从已分类为药品类的材料中提取结构化用药信息，结合知识库补充适应症和注意事项，区分信息来源（材料原文 vs 知识库补充），生成大字版用药卡。

### 输入

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `material_id` | string | 是 | 材料唯一标识 |
| `ocr_text` | string | 是 | WF-1 输出的 OCR 文字 |
| `image_description` | string | 是 | WF-1 输出的图片视觉描述 |
| `material_type` | string | 是 | 用户确认后的材料类型 |
| `user_dose_note` | string | 否 | 用户额外输入的医生口头医嘱 |

### 输出

Medicine 对象（完整结构见 `docs/数据结构.md`）

关键字段：
- `name` / `specification` / `dose_from_material` / `frequency_from_material` / `timing_from_material`：用药卡核心信息
- `name_source` / `dose_source` 等：每个字段的来源标注
- `purpose`：知识库补充的适应症通俗解释
- `warnings`：合并后的注意事项（区分 material / knowledge_base 来源）
- `needs_confirmation`：需要医生或药师确认的问题
- `knowledge_found`：知识库是否查询到该药品
- `authenticity_verification`：仿冒药深度核验结果（基于知识库比对，WF-1 仅做初筛）

### 节点设计（设计阶段）

| 节点编号 | 节点名称 | 节点类型 | 说明 |
|---------|---------|---------|------|
| N1 | 药品字段提取 | LLM文本 | 从 OCR 文字中提取药名、规格、用量等，标注是否在材料中明确出现 |
| N2 | 知识库查询 | 知识库 | 根据药名查询药品知识库 |
| N2.5 | 仿冒药深度核验 | 知识库+LLM文本 | 基于知识库比对批准文号、包装样式、厂家信息是否与备案一致 |
| N3 | 来源标注与合并 | LLM文本 | 合并材料提取结果与知识库结果，每个字段标注来源 |
| N4 | 确认问题生成 | LLM文本 | 识别药名模糊、剂量缺失、处方与说明书不一致等问题 |
| N5 | 注意事项整理 | LLM文本 | 合并禁忌、不良反应、特殊人群提醒 |
| N6 | 输出格式化 | Code | 校验字段、组装 Medicine JSON（含 authenticity_verification） |

### 使用知识库

| 知识库名称 | 提供方 | 查询方式 | 返回内容 |
|-----------|--------|---------|---------|
| 药品知识库 | B | 药名精确查询 + 模糊匹配 | 适应症通俗解释、常见不良反应、禁忌、储存要求、药品分类 |
| 药品备案数据库 | B | 批准文号精确查询 + 厂家名称匹配 | 国药准字备案信息、包装样式参考、厂家注册信息 |

### 接口基线（供 WF-2 开发参考）

WF-2 的输入来自 WF-1 输出的 Material 对象，通过 Next.js API 层传递：

```
confirm 页面用户确认 → POST /api/medicine
  ↓
API 从 sessionStorage 读取 Material（material_id, ocr_text, image_description, material_type）
  ↓
调用 WF-2
  ↓
返回 Medicine 对象
  ↓
medicine/page.tsx 从 sessionStorage 读取展示
```

**WF-2 开发前需确认**：
1. B 的药品知识库是否已上线
2. 知识库查询接口格式（参考 `workflow/WF1说明.md` 中 C→B 接口定义）
3. WF-2 的 Coze Workflow URL（部署后补充）

### 安全约束

| 约束 | 实现方式 |
|------|---------|
| 材料未提及的剂量，绝不补全 | dose/frequency/timing 的 source 为 "null" 时，前端显示"材料未说明" |
| 药名模糊时不继续推断 | 标记 needs_confirmation，提示用户重新拍摄或手动输入 |
| 不出现"建议停药/换药/改量" | Prompt 约束 |
| 处方与说明书不一致时标注 | needs_confirmation 中生成"以医生处方为准" |
| 区分材料原文与知识库补充 | 每个字段标注 source |

## WF-3：健康消费防骗分析

### 目标

从防骗类材料中识别身份风险、宣传风险、交易风险、情绪操控风险四类信号，基于硬编码规则判定风险等级（绿/黄/红），生成行动建议和核验步骤。

### 输入

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `material_id` | string | 是 | 材料唯一标识 |
| `ocr_text` | string | 是 | WF-1 输出的 OCR 文字 |
| `image_description` | string | 是 | WF-1 输出的图片视觉描述 |
| `material_type` | string | 是 | 用户确认后的材料类型 |

### 输出

Risk 对象（完整结构见 `docs/数据结构.md`）

关键字段：
- `risk_level`：风险等级（green / yellow / red），由 Code 节点硬编码判定
- `signals`：风险信号列表，每条含 category、evidence_text（必填）、reason、stop_action
- `stop_actions`：当前应立即停止的操作
- `verification_steps`：下一步核验方式
- `evidence_to_keep`：需要保存的证据
- `red_alert`：仅红色风险时存在，固定文案

### 节点设计（设计阶段）

| 节点编号 | 节点名称 | 节点类型 | 说明 |
|---------|---------|---------|------|
| N1 | 材料预分析 | LLM文本 | 提炼材料中的关键事实清单 |
| N2 | 身份风险扫描 | LLM文本 | 检查是否冒充官方、机构信息是否清晰 |
| N3 | 宣传风险扫描 | LLM文本 | 检查是否声称包治百病、可替代处方药等 |
| N4 | 交易风险扫描 | LLM文本 | 检查是否私人转账、限时催付、索要敏感信息 |
| N5 | 情绪操控扫描 | LLM文本 | 检查是否威胁恐吓、不让告诉子女等 |
| N6 | 风险等级判定 | Code | 根据硬编码规则判定 green/yellow/red |
| N7 | 行动建议生成 | LLM文本 | 根据风险等级生成 stop_actions / verification_steps / evidence_to_keep |
| N8 | 输出格式化 | Code | 组装 Risk JSON |

**节点并行设计**：N2/N3 可并行执行，N4/N5 可并行执行，不依赖彼此结果。

### 使用知识库

| 知识库名称 | 提供方 | 查询方式 | 返回内容 |
|-----------|--------|---------|---------|
| 风险规则库 | B | 规则全文加载到 Prompt | 典型骗术话术模式、风险判定规则、核查建议模板 |
| 保健品备案库 | B（可选） | 产品名称查询 | 蓝帽子备案号、产品合规状态 |

### 接口基线（供 WF-3 开发参考）

```
confirm 页面用户确认 → POST /api/fraud
  ↓
API 从 sessionStorage 读取 Material（material_id, ocr_text, image_description, material_type）
  ↓
调用 WF-3
  ↓
返回 Risk 对象
  ↓
fraud/page.tsx 从 sessionStorage 读取展示
```

### 风险等级判定规则

由 N6 Code 节点硬编码，不交由 LLM：

| 等级 | 判定条件 |
|------|---------|
| red | 出现以下任一：索要验证码/身份证/银行卡；私人转账要求；诱导停药；冒充医生/官方；威胁恐吓；不让告诉子女 |
| yellow | 无红色信号，但存在任意风险信号 |
| green | 无任何风险信号 |

### 安全约束

| 约束 | 实现方式 |
|------|---------|
| 每条风险必须有原文证据 | signals[].evidence_text 必填，必须引用 OCR 原文 |
| 不只根据单个关键词判断 | Prompt 要求综合多个信号判定 |
| 不无证据判定诈骗 | 每条 signal 必须有 evidence_text 和 reason |
| 不使用恐吓语言 | risk_description 和 stop_actions 使用中性、具体的行动语言 |
| 红色风险固定提示 | red_alert.headline 为固定文案，不由 LLM 生成 |

## WF-4：家属简报

### 目标

汇总已有的药品解读结果和/或防骗分析结果，生成面向子女或照护者的结构化简报。简报包含材料摘要、财务与信息安全、风险等级、关键证据和行动建议。

### 输入

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `material_id` | string | 是 | 材料唯一标识 |
| `material_type` | string | 是 | 材料类型 |
| `ocr_text` | string | 是 | OCR 文字 |
| `medicine` | Medicine \| null | 否 | WF-2 的输出结果（药品类材料时传入） |
| `risk` | Risk \| null | 否 | WF-3 的输出结果（防骗类材料时传入） |

**约束**：medicine 和 risk 至少有一个非 null。

### 输出

FamilyBrief 对象（完整结构见 `docs/数据结构.md`）

关键字段：
- `material_summary`：一句话概括上传了什么
- `product_or_person`：涉及的产品或人员
- `payment_status` / `payment_amount`：付款情况
- `stop_medicine_request`：是否被要求停药
- `personal_data_exposed`：是否泄露敏感信息
- `highest_risk`：最高风险等级
- `key_evidence`：最多 3 条关键风险证据
- `next_actions`：家属下一步建议
- `copy_text`：预格式化的纯文本简报全文

### 节点设计（设计阶段）

| 节点编号 | 节点名称 | 节点类型 | 说明 |
|---------|---------|---------|------|
| N1 | 材料摘要生成 | LLM文本 | 用一句话概括老人上传了什么材料 |
| N2 | 财务与信息安全提取 | LLM文本 | 从 OCR 文字和风险结果中提取付款状态、敏感信息泄露情况 |
| N3 | 风险聚合与建议生成 | LLM文本 | 汇总风险等级、提取关键证据、生成行动建议 |
| N4 | 输出格式化 | Code | 组装 FamilyBrief JSON |

### 使用知识库

无。全部从输入数据（Medicine / Risk / OCR）推导。

### 安全约束

| 约束 | 实现方式 |
|------|---------|
| 不自动发送给家属 | 简报仅生成可复制内容（copy_text），由用户主动转发 |

| 无法确认的填"暂未确认" | payment_amount 等字段不臆测 |
