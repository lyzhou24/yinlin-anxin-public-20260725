## 2. 文件上传接口

### POST /api/upload

**说明**：将用户选择的图片文件上传到 Coze 沙箱对象存储（S3 兼容），返回公网可访问的签名 URL。

**状态**：已实现。

**对象存储**：使用 `coze-coding-dev-sdk` 的 `S3Storage`，环境变量由 `coze dev` 自动注入：
- `COZE_BUCKET_ENDPOINT_URL` — S3 代理端点
- `COZE_BUCKET_NAME` — 桶名称
- `COZE_WORKLOAD_IDENTITY_*` — Workload Identity 认证

#### 请求

**Content-Type**：`multipart/form-data`

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `file` | File | 是 | 用户上传的图片文件，支持 JPG/PNG/JPEG |

#### 响应

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `file_url` | string | 对象存储签名 URL，有效期 1 小时，公网可访问 |

**成功响应示例**：

``` json
{
  "success": true,
  "data": {
    "file_url": "https://coze-coding-project.tos.coze.site/coze_storage_7662765024183844874/materials/1784392607720_8xv54m_2f4108bb.png?sign=1784396207-..."
  },
  "error_code": null,
  "error_message": null
}
```

#### 错误码

| 错误码 | 说明 |
|--------|------|
| `MISSING_FILE` | 未提供文件，请选择一张图片 |
| `UNSUPPORTED_FILE` | 文件格式不支持，请上传 JPG 或 PNG 格式的照片 |
| `FILE_TOO_LARGE` | 文件过大，请压缩后重试（最大 10MB） |
| `UPLOAD_FAILED` | 文件上传失败，请稍后重试 |

**错误响应示例**：

``` json
{
  "success": false,
  "data": null,
  "error_code": "UNSUPPORTED_FILE",
  "error_message": "文件格式不支持，请上传 JPG 或 PNG 格式的照片"
}
```

## 3. 材料分析接口（WF-1）

### POST /api/upload/analyze

**接口名称**：材料预处理与分类

**作用**：接收图片文件地址，调用 Coze WF-1 工作流，依次完成：

1.  文件基本校验
2.  图片清晰度评估
3.  OCR 文字提取
4.  图片内容理解
5.  材料分类判断
6.  路由决策

最终返回完整的 Material v2 对象。

**状态**：已部署并接入前端。

**Coze WF-1 部署信息**：
- 项目 ID：`7663130612399620105`
- 端点：`POST https://wxzr85dnjt.coze.site/run`
- 认证：`Authorization: Bearer ${COZE_TOKEN}`
- 响应包装：`{ material_json: Material, run_id: string }`

------------------------------------------------------------------------

### 3.1 请求

**Content-Type**：`application/json`

  -------------------------------------------------------------------------------------------------------------------------------------------
  字段名                   类型             必填             说明
  ------------------------ ---------------- ---------------- --------------------------------------------------------------------------------
  `file_url`               string           是               对象存储中的图片文件地址，由 /api/upload 接口返回
  -------------------------------------------------------------------------------------------------------------------------------------------

**请求示例**：

``` json
{
  "file_url": "https://coze-coding-project.tos.coze.site/coze_storage_xxx/materials/xxx.jpg?sign=xxx"
}
```

------------------------------------------------------------------------

### 3.2 成功响应

**HTTP 状态码**：200

`data` 字段返回完整 Material 对象：

  -------------------------------------------------------------------------------------------------------
  字段名                      类型             必填             说明
  --------------------------- ---------------- ---------------- -----------------------------------------
  `material_id`               string           是               WF-1 生成的唯一标识，格式 `mat_` +
                                                                时间戳后8位 + 随机4位

  `file_url`                  string           是               原始文件地址，原样返回

  `material_type`             string           是               分类标签，11 种之一（见下方枚举）

  `type_label`                string           是               中文分类名，用于前端直接展示

  `confidence`                number           是               分类置信度，0.0 - 1.0

  `confidence_level`          string           是               置信度等级：`high` / `medium` / `low`

  `quality`                   object           是               图片质量评估结果（is_clear / quality_score / issues）

  `ocr_text`                  string           是               OCR 提取的全部文字，保持原始换行

  `image_description`         string           是               图片视觉特征描述（JSON 字符串）

  `missing_fields`            string\[\]       是               未能从图片中识别的字段列表，可为空数组

  `route`                     string           是               路由方向：`medicine` / `fraud` /
                                                                `manual_confirm`

  `classification_reason`     string           是               LLM 给出的分类理由，用于调试

  `sensitive_info_detected`   object           是               隐私信息检测结果（见下方子结构）

  `authenticity_flags`        object/null      是               药品真实性风险初筛结果（非药品返回 null）
  -------------------------------------------------------------------------------------------------------

> **注意**：Coze WF-1 的原始返回包裹在 `material_json` 对象中，还包含 `run_id` 字段。
> 后端 `/api/analyze` 会提取 `material_json` 内部字段直接返回，`run_id` 附加在顶层。
> 即前端收到的实际结构为 `{ success, data: { ...Material各字段, run_id }, error_code, error_message }`


**quality 子结构：**

```json
{
  "is_clear": true,
  "quality_score": 0.92,
  "issues": []
}
```

字段说明：

|字段|类型|说明|
|-|-|-|
|is_clear|boolean|图片是否满足分析要求|
|quality_score|number|图片质量评分，范围0-1|
|issues|array|图片问题列表|

**material_type 枚举值**：

  值                        type_label       route
  ------------------------- ---------------- ----------------
  `regular_medicine`        正规药品         medicine
  `medicine_leaflet`        药品说明书       medicine
  `hospital_prescription`   医院处方         medicine
  `multiple_medicines`      多种药品         medicine
  `health_supplement`       保健食品         fraud
  `ordinary_food`           普通食品         fraud
  `medical_device`          医疗器械         fraud
  `health_promotion`        健康宣传材料     fraud
  `sales_chat`              推销聊天记录     fraud
  `payment_proof`           订单或付款凭证   fraud
  `unknown`                 暂时无法判断     manual_confirm

**confidence_level 映射**：

  confidence 范围   confidence_level   前端展示
  ----------------- ------------------ ------------------------
  \>= 0.85          high               高置信度
  0.50 - 0.84       medium             中等置信度
  \< 0.50           low                低置信度，触发强制确认

**特殊路由规则**：当 `confidence < 0.5` 时，无论 `material_type`
是什么，`route` 强制为 `manual_confirm`。

**sensitive_info_detected 子结构**（隐私信息检测结果）：

  ------------------------------------------------------------------------------------------
  字段名                       类型                  说明
  ---------------------------- --------------------- ---------------------------------------
  `has_sensitive_info`         boolean               是否检测到隐私信息

  `detected_types`             string\[\]            检测到的隐私类型列表，枚举：`id_card` /
                                                     `bank_card` / `verification_code` /
                                                     `phone_number` / `address` /
                                                     `medical_record_number` / `qr_code`

  `detected_types_labels`      string\[\]            对应中文标签：身份证 / 手机号 / 地址 /
                                                     银行卡 / 姓名 / 病历号 /
                                                     二维码

  `user_confirmed`             boolean               用户是否已确认继续（前端传入
                                                     `skip_sensitive_check=true` 时为 true）
  ------------------------------------------------------------------------------------------

**隐私信息检测流程**（对应 A 的 2.0 文档 3.1 步骤 2-3）：

    WF-1 图片理解节点在 N4 中同时检测隐私信息
      │
      ├── has_sensitive_info = false → 正常流程，不拦截
      │
      └── has_sensitive_info = true → 以下逻辑在前端执行：
           ├── 前端高亮标记敏感区域（如能定位）
           ├── 展示提示："检测到图片中可能包含身份证/银行卡/验证码等敏感信息，建议遮挡后重新拍摄"
           ├── 按钮 A："重新上传" → 返回 /upload
           ├── 按钮 B："我已确认，继续识别" → 重新调 /api/analyze（带 skip_sensitive_check=true）
           └── 按钮 C："取消上传" → 返回首页

**注意**：隐私信息检测是 WF-1 内部的一个附加判断，不是独立的 API
调用。前端不需要先调一个检测接口再调分析接口，而是在首次调用
`/api/analyze` 时，返回结果中自动包含
`sensitive_info_detected`。如果检测到敏感信息且
`user_confirmed=false`，前端应暂停并让用户确认。

------------------------------------------------------------------------

**authenticity_flags 子结构**（仿冒药/假药初步判断）：

  -------------------------------------------------------------------------------------
  字段名                       类型                  说明
  ---------------------------- --------------------- ----------------------------------
  `authenticity_level`         string                仿冒风险等级：`likely_authentic` /
                                                     `needs_verification` /
                                                     `suspected_counterfeit`

  `authenticity_level_label`   string                中文标签："初步判断为正品" /
                                                     "需进一步核验" / "疑似仿冒"

  `risk_signals`               string\[\]            触发风险的具体信号列表

  `verification_suggestions`   string\[\]            建议的核验方式
  -------------------------------------------------------------------------------------

**authenticity_level 判定逻辑**（仅当 material_type 为药品类时触发）：

非药品材料：

```json
"authenticity_flags": null
```

药品材料返回对象。

判定逻辑（在 WF-1 中附加判断，仅用于风险提示）：

    likely_authentic（初步判断为正品）：
      - 批准文号格式正确（国药准字Z/H/S+8位数字）
      - 生产厂家信息清晰
      - 包装印刷质量良好，无明显异常

    needs_verification（需进一步核验）：
      - 批准文号格式异常或不完整
      - 生产厂家信息模糊或缺失
      - 无法确认信息来源

    suspected_counterfeit（疑似仿冒）：
      - 批准文号格式明显不符合规范
      - 同一批准文号与国家药监局数据库不匹配（需 B 知识库支持）
      - 包装存在明显印刷质量问题（字迹模糊、颜色异常、拼写错误）
      - 药品名称与知名药品高度相似但存在细微差异

**重要边界**：

-   `authenticity_flags` 是 WF-1 的**初步筛查结果**，不是最终判定
-   `suspected_counterfeit`
    不等于"这是假药"，只表示"存在疑似仿冒的特征，需要专业核验"
-   WF-2（药品解读）会结合知识库做更深入的核验，WF-1
    只做视觉+OCR层面的初步判断。WF-1
    不负责数据库真实性查询，避免将风险提示误解为假药最终判定
-   对前端展示而言：`likely_authentic` 不额外提示；`needs_verification`
    在确认页展示黄色提示；`suspected_counterfeit`
    在确认页和药品结果页展示红色提示，文案为"该药品存在疑似仿冒特征，建议到正规药店或拨打12331核验"

  ------------------------------------------------------------------------------------------------------------------------
  判断层级           负责人           判断依据                                       输出位置
  ------------------ ---------------- ---------------------------------------------- -------------------------------------

                     知识库）                                                        输出，设计阶段）

  知识库数据         B                国家药监局批准文号数据库                       药品知识库
  ------------------------------------------------------------------------------------------------------------------------

  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  错误码                      触发条件                           error_message                                                                            用户应做什么
  --------------------------- ---------------------------------- ---------------------------------------------------------------------------------------- --------------------------------------
  `MISSING_FILE_URL`          请求未包含 file_url 参数           缺少文件地址参数                                                                         检查请求参数
  `BLURRY_IMAGE`              WF-1 清晰度评估不通过              照片不够清晰，建议对准材料重新拍摄。注意保持手稳、光线充足。                             重新拍摄并上传
  `OCR_FAILED`                OCR 提取结果为空或仅含             未能识别文字，请调整光线后重试。如果图片中主要是图片而非文字，请补充上传相关文字材料。   调整拍摄条件后重试
                              \[无法识别\]                                                                                                                
  `CLASSIFICATION_FAILED`     分类节点返回异常或无法解析         系统暂时无法判断材料类型，请手动选择材料类型。                                           手动选择分类
  `IMAGE_TOO_SMALL`           图片尺寸过小（< 14px）            图片尺寸过小，请上传清晰的原图。                                                         上传更大尺寸的图片

  `COZE_API_ERROR`            Coze Workflow                      分析服务暂时不可用，请稍后重试。                                                         稍后重试
                              调用失败（网络、鉴权、额度等）                                                                                              
  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**错误响应示例**：

``` json
{
  "success": false,
  "data": null,
  "error_code": "BLURRY_IMAGE",
  "error_message": "照片不够清晰，建议对准材料重新拍摄。注意保持手稳、光线充足。"

```

**COZE_API_ERROR 严重场景**：

当 Coze 平台本身不可用时，后端返回 HTTP 502。前端应对 502 做统一兜底处理，展示"分析服务暂时不可用，请稍后重试"。

**COZE_TOKEN 未配置场景**：

当 `COZE_TOKEN` 环境变量未设置时，后端返回 HTTP 500，`error_code: COZE_API_ERROR`，`error_message: "分析服务配置异常，请联系管理员"`。

### 3.4 前后端调用流程

    用户选择图片（upload/page.tsx）
         │
         │  本地预览：URL.createObjectURL()
         │  用户点击「开始分析」
         │
         ▼
    Step 1: POST /api/upload（文件上传接口）
         │  输入: File (multipart/form-data)
         │  后端: 上传到 Coze 沙箱对象存储（S3Storage）
         │  输出: { file_url }（签名 URL，1小时有效）
         │
         ▼
    Step 2: POST /api/analyze（本接口）
         │  输入: { file_url }
         │  后端: 调用 Coze WF-1
         │  WF-1 内部: 图片理解+OCR→分类→隐私检测→仿冒药初筛→路由→聚合
         │  输出: Material v2 对象 + run_id
         │
         ├── success = true
         │     │
         │     ▼
         │  前端将 Material 存入 sessionStorage
         │  key: "material_json"
         │  value: 完整 Material v2 JSON
         │     │
         │     ▼
         │  跳转到 /confirm?material_id=mat_xxx
         │     │
         │     ▼
         │  confirm/page.tsx 从 sessionStorage 读取 Material
         │  展示：type_label / confidence / confidence_level / ocr_text / classification_reason
         │  展示敏感信息检测结果（如有）→ 显示遮挡建议
         │  展示药品真伪存疑标记（如有）
         │     ├── authenticity_flags.authenticity_level = "suspected_counterfeit" → 红色警告
         │     └── authenticity_flags.authenticity_level = "needs_verification" → 黄色提示
         │  用户确认或修正分类
         │     │
         │     ├── route = "medicine" → /medicine
         │     ├── route = "fraud"    → /fraud
         │     └── route = "manual_confirm" → 停留本页，用户手动选择
         │
         └── success = false
               │
               ▼
          前端根据 error_code 展示对应错误页
               ├── BLURRY_IMAGE          → 提示重新拍摄
               ├── OCR_FAILED            → 提示调整光线重试
               ├── IMAGE_TOO_SMALL       → 提示上传更大图片
               ├── CLASSIFICATION_FAILED → 跳转确认页手动选择
               └── COZE_API_ERROR        → 提示稍后重试

**关键约定**：

1.  **sessionStorage 存储**：Material 对象包含 `ocr_text`（可能很长），不适合放在 URL query 中。使用 `sessionStorage` 存储（key: `material_json`），URL 只传 `material_id` 作为索引。
2.  **confirm 页面从 sessionStorage 读取**：已实现，通过 `sessionStorage.getItem("material_json")` 获取完整 Material v2。
3.  **用户修正分类后不重跑 WF-1**：用户在确认页手动选择不同的 `material_type` 时，前端直接覆盖 `material_type` 和 `route`，不重新调用 `/api/analyze`。
4.  **敏感信息处理由前端主导**：WF-1 只负责检测和标记（`sensitive_info_detected`），是否继续由用户决定。前端根据 `has_sensitive_info` 展示提示。
5.  **真伪初筛结果随 Material 传递**：`authenticity_flags` 仅在 `route = "medicine"` 时有实际意义，前端在确认页和药品结果页均需展示。

## 8. 错误码汇总

  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------
  错误码                    HTTP 状态码              对应场景                             用户提示                                                       触发接口
  ------------------------- ------------------------ ------------------------------------ -------------------------------------------------------------- ---------------
  `INVALID_FILE_TYPE`       400                      文件格式不支持                       请上传 JPG 或 PNG 格式的照片                                   /api/upload
  `FILE_TOO_LARGE`          400                      文件超过 10MB                        图片太大，请压缩后重试                                         /api/upload
  `UPLOAD_FAILED`           500                      对象存储上传失败                     文件上传失败，请稍后重试                                       /api/upload
  `MISSING_FILE_URL`        400                      未传 file_url 参数                   缺少文件地址参数                                               /api/analyze
  `BLURRY_IMAGE`            502                      图片模糊（WF-1 返回）               照片不够清晰，建议对准材料重新拍摄。注意保持手稳、光线充足。   /api/analyze
  `OCR_FAILED`              502                      OCR 识别失败（WF-1 返回）           未能识别文字，请调整光线后重试                                 /api/analyze
  `CLASSIFICATION_FAILED`   502                      分类节点异常（WF-1 返回）           系统暂时无法判断材料类型，请手动选择                           /api/analyze
  `COZE_API_ERROR`          502                      Coze 工作流调用失败                  分析服务暂时不可用，请稍后重试                                 /api/analyze
  `COZE_TOKEN_MISSING`      500                      COZE_TOKEN 环境变量未配置           分析服务配置异常，请联系管理员                                 /api/analyze
  `LOW_CONFIDENCE`          ---                      分类置信度过低（非错误，正常返回）   当前材料识别不够确定，请手动选择材料类型                       /api/analyze
  `KNOWLEDGE_NOT_FOUND`     `<!-- TODO -->`{=html}   知识库未命中                         知识库暂无该药品信息，建议咨询药师                             /api/medicine
  `WORKFLOW_TIMEOUT`        `<!-- TODO -->`{=html}   工作流超时                           分析超时，请稍后重试                                           全部
  `DATABASE_ERROR`          `<!-- TODO -->`{=html}   数据库错误                           保存失败，请稍后重试                                           /api/history
  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------

**说明**：
- `LOW_CONFIDENCE` 不是错误，是 Material 对象中 `confidence_level = "low"` + `route = "manual_confirm"` 的情况，前端正常跳转确认页
- `COZE_API_ERROR` / `BLURRY_IMAGE` / `OCR_FAILED` / `CLASSIFICATION_FAILED` 返回 HTTP 502，表示上游（WF-1）处理异常
- `COZE_TOKEN_MISSING` 返回 HTTP 500，属于服务端配置问题
- `INVALID_FILE_TYPE` / `MISSING_FILE_URL` 返回 HTTP 400，属于客户端参数错误
