## 1. Material 对象（v2）

WF-1 输出，作为后续所有流程的输入基础。

| 字段名 | 类型 | 必填 | 说明 | 数据来源 |
|--------|------|------|------|---------|
| `material_id` | string | 是 | 唯一标识，格式 `mat_` + 时间戳后8位 + 随机4位 | LLM 生成 |
| `file_url` | string | 是 | 原始文件地址，原样返回 | 用户输入 |
| `material_type` | string | 是 | 分类标签，11 种之一（见下方枚举） | LLM 生成（分类节点） |
| `type_label` | string | 是 | 中文分类名，用于前端直接展示 | LLM 生成（分类节点） |
| `confidence` | number | 是 | 分类置信度，0.0 - 1.0 | LLM 生成（分类节点） |
| `confidence_level` | string | 是 | 置信度等级：`high` / `medium` / `low` | 规则判断（由 confidence 计算） |
| `quality` | object | 是 | 图片质量评估（见下方说明） | LLM 生成（OCR 节点） |
| `ocr_text` | string | 是 | OCR 提取的全部文字，保持原始换行 | OCR |
| `image_description` | string | 是 | 图片视觉特征描述（JSON 字符串） | 视觉模型 |
| `missing_fields` | string[] | 是 | 未能从图片中识别的字段列表 | LLM 生成 |
| `route` | string | 是 | 路由方向：`medicine` / `fraud` / `manual_confirm` | 规则判断 |
| `classification_reason` | string | 是 | LLM 给出的分类理由 | LLM 生成（分类节点） |
| `sensitive_info_detected` | object | 是 | 隐私信息检测结果 | LLM 生成（隐私检测节点） |
| `authenticity_flags` | object | 是 | 仿冒药/假药初步判断结果 | LLM 生成（仿冒初筛节点） |

### material_type 枚举

| 值 | type_label | route | 数据来源 |
|----|-----------|-------|---------|
| `regular_medicine` | 正规药品 | medicine | 分类节点 |
| `medicine_leaflet` | 药品说明书 | medicine | 分类节点 |
| `hospital_prescription` | 医院处方 | medicine | 分类节点 |
| `multiple_medicines` | 多种药品 | medicine | 分类节点 |
| `health_supplement` | 保健食品 | fraud | 分类节点 |
| `ordinary_food` | 普通食品 | fraud | 分类节点 |
| `medical_device` | 医疗器械 | fraud | 分类节点 |
| `health_promotion` | 健康宣传材料 | fraud | 分类节点 |
| `sales_chat` | 推销聊天记录 | fraud | 分类节点 |
| `payment_proof` | 订单或付款凭证 | fraud | 分类节点 |
| `unknown` | 暂时无法判断 | manual_confirm | 分类节点 |

### confidence_level 映射规则

| confidence 范围 | confidence_level | 前端展示 |
|----------------|-----------------|---------|
| >= 0.85 | `high` | 高置信度，直接展示 |
| 0.50 - 0.84 | `medium` | 中等置信度，标注提示 |
| < 0.50 | `low` | 低置信度，强制手动确认 |

### quality 字段说明

WF-1 实际返回 `quality` 为 object 结构：

```json
{
  "is_clear": true,
  "quality_score": 0.92,
  "issues": []
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `is_clear` | boolean | 图片是否清晰 |
| `quality_score` | number | 质量评分 0-1 |
| `issues` | string[] | 质量问题列表（如"光线不足"、"文字模糊"） |

> ⚠️ 当前 TypeScript 类型定义为 `quality: ImageQuality`（string: "good"/"fair"/"poor"），与 WF-1 实际输出不一致，待后续对齐。

## 2. AuthenticityFlags 子结构

仿冒药/假药初步判断结果，仅当 `material_type` 为药品类时有实际意义。

| 字段名 | 类型 | 必填 | 说明 | 数据来源 |
|--------|------|------|------|---------|
| `authenticity_level` | string | 是 | 仿冒风险等级（见下方枚举） | LLM 生成（仿冒初筛节点） |
| `authenticity_level_label` | string | 是 | 中文标签 | LLM 生成（仿冒初筛节点） |
| `risk_signals` | AuthenticityRiskSignal[] | 是 | 触发风险的具体信号列表 | LLM 生成（仿冒初筛节点） |
| `verification_suggestions` | string[] | 是 | 建议的核验方式 | LLM 生成（仿冒初筛节点） |

### authenticity_level 枚举

| 值 | authenticity_level_label | 说明 | 前端展示 |
|----|------------------------|------|---------|
| `likely_authentic` | 初步判断为正品 | 批准文号格式正确、厂家清晰、包装正常 | 不额外提示 |
| `needs_verification` | 需进一步核验 | 批准文号异常或不完整、厂家模糊 | 黄色提示 |
| `suspected_counterfeit` | 疑似仿冒 | 批准文号明显不符、印刷质量差、药名高度相似 | 红色警告 |
| `not_applicable` | 不适用 | 非药品类材料 | 不展示 |

### AuthenticityRiskSignal 子结构

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `signal_type` | string | 是 | 信号类型：`name_similarity` / `print_quality` / `missing_standard_info` / `approval_number_format` |
| `description` | string | 是 | 信号描述 |
| `reference_product` | string | 否 | 参考的正品名称（仅 name_similarity 类型时提供） |

### 判定逻辑

```
likely_authentic：
  - 批准文号格式正确（国药准字Z/H/S+8位数字）
  - 生产厂家信息清晰
  - 包装印刷质量良好，无明显异常

needs_verification：
  - 批准文号格式异常或不完整
  - 生产厂家信息模糊或缺失
  - 无法确认信息来源

suspected_counterfeit：
  - 批准文号格式明显不符合规范
  - 同一批准文号与国家药监局数据库不匹配（需 B 知识库支持）
  - 包装存在明显印刷质量问题（字迹模糊、颜色异常、拼写错误）
  - 药品名称与知名药品高度相似但存在细微差异
```

### 安全边界

- `suspected_counterfeit` 不等于"这是假药"，仅表示"存在疑似仿冒的特征，需要专业核验"
- WF-1 只做视觉+OCR 层面的初步判断，不做数据库真实性查询
- WF-2（药品解读）会结合知识库做更深入核验

### 分工

| 判断层级 | 负责人 | 判断依据 | 输出位置 |
|---------|--------|---------|---------|
| WF-1 初步筛查 | C | OCR+视觉特征 | `Material.authenticity_flags` |
| WF-2 深度核验 | C（调用 B 知识库） | 药品知识库比对 | `Medicine.authenticity_check`（WF-2 输出，设计阶段） |
| 知识库数据 | B | 国家药监局批准文号数据库 | 药品知识库 |

## 3. SensitiveInfoDetected 子结构

隐私信息检测结果，由 WF-1 的隐私检测节点输出。

| 字段名 | 类型 | 必填 | 说明 | 数据来源 |
|--------|------|------|------|---------|
| `has_sensitive_info` | boolean | 是 | 是否检测到隐私信息 | LLM 生成（隐私检测节点） |
| `detected_types` | string[] | 是 | 检测到的隐私类型列表 | LLM 生成（隐私检测节点） |
| `detected_types_labels` | string[] | 是 | 对应中文标签列表 | LLM 生成（隐私检测节点） |
| `user_confirmed` | boolean | 是 | 用户是否已确认继续 | 用户输入（前端传入） |

### detected_types 枚举

| 类型值 | 中文标签 (detected_types_labels) | 说明 |
|--------|------|------|
| `id_card` | 身份证号 | 18位身份证号 |
| `bank_card` | 银行卡号 | 16-19位银行卡号 |
| `verification_code` | 验证码 | 短信/支付验证码 |
| `phone_number` | 手机号 | 11位手机号 |
| `address` | 住址 | 详细家庭住址 |
| `medical_record_number` | 病历号 | 医院病历编号 |
| `qr_code` | 二维码 | 可能包含个人信息的二维码 |
| `name` | 姓名 | 真实姓名 |

### 前端处理流程

```
has_sensitive_info = false → 正常流程，不拦截

has_sensitive_info = true：
  ├── 前端高亮标记敏感区域
  ├── 展示提示："检测到图片中可能包含身份证/银行卡/验证码等敏感信息，建议遮挡后重新拍摄"
  ├── 按钮 A："重新上传" → 返回 /upload
  ├── 按钮 B："我已确认，继续识别" → 设 user_confirmed = true，继续后续流程
  └── 按钮 C："取消上传" → 返回首页
```

## 7. 类型差异说明

以下为当前文档与 TypeScript 代码（`src/lib/types.ts`）之间的已知差异，需后续对齐：

| 字段 | 文档（WF-1 实际输出） | TypeScript 类型 | 对齐方向 |
|------|---------------------|----------------|---------|
| `quality` | `object`（含 is_clear/quality_score/issues） | `ImageQuality`（string: "good"/"fair"/"poor"） | types.ts 需改为 object |
| `SensitiveInfoDetected.detected_types` | `string[]`（枚举值） | `SensitiveInfoType[]` | 已一致 ✅ |
| `SensitiveInfoDetected.detected_types_labels` | `string[]`（中文标签） | `string[]` | 已一致 ✅ |
| `SensitiveInfoDetected.user_confirmed` | `boolean` | `boolean` | 已一致 ✅ |
| `AuthenticityFlags.authenticity_level` | `string`（枚举值） | `AuthenticityLevel` | 已一致 ✅ |
| `AuthenticityFlags.authenticity_level_label` | `string` | `string` | 已一致 ✅ |
| `AuthenticityFlags.risk_signals` | `AuthenticityRiskSignal[]` | `AuthenticityRiskSignal[]` | 已一致 ✅ |
| `AuthenticityFlags.verification_suggestions` | `string[]` | `string[]` | 已一致 ✅ |

**唯一实质差异**：`quality` 字段，WF-1 返回 object，types.ts 定义为 string。前端 confirm 页面已按 object 方式展示，后续需更新 types.ts。
